# 49 — Model-agnostic product test cases

> Status: DEC-055 benchmark specification; no product result is claimed. This is a scenario and oracle catalog, not evidence that the implementation passes. Each case is run against a pinned app build, agent/harness/model, account, permissions, machine, dataset and clock. `08` owns requirements, `09` traceability, `42` implementation evidence, `47` competitor protocol. Never compare different task inputs or omit unsupported cases.

## 1. Measurement contract

For every run record: `CASE`, input fixture digest, allowed capabilities, agent/model and versions, hardware/OS, account plan, user expertise, policy profile, start/end UTC, time to first useful response, time to finished artifact, active human time, prompts/corrections, approvals, tool calls, tokens/cost where available, CPU/RAM/energy when relevant, crashes, recovered state, final outputs and evidence links. Score **intent correctness**, effect correctness, artifact fidelity, completeness, citation accuracy, recoverability and user experience separately. A task is `PASS` only when its explicit oracle passes; `reported_done` is a distinct state. Label unsupported, unavailable, blocked by account, inconclusive and not run separately from failure. Use at least five independent runs per case for comparisons; publish median, p95, variance and raw failures. Blind human reviewers judge utility and visual quality. Avoid declaring “100% accurate” from a finite suite.

The clock includes setup and approval delay in an end-to-end result; also report agent-active time separately. No case passes by hiding manual user work. Seed deterministic fixtures for local/API cases and capture the external state at start for live web cases. Reset fixture state between repetitions. Fault injection is part of the case, not an optional afterthought. Human studies recruit nontechnical and technical users with separate results; a strong power-user score cannot substitute for first-run comprehension.

**Execution record per case and repetition:**

| Field | Required entry |
|---|---|
| Problem | Exact user request, fixture/version and initial external state |
| Expected | Task outcome, allowed effects, time/resource envelope and acceptance oracle from the case row |
| Observed | What the product actually did: actions, intermediate states, output version, time/cost, user interventions, failures and recovery steps; `not run` until measured |
| Verdict | `pass|fail|unsupported|blocked_by_access|inconclusive|not_run`, with oracle result and reviewer |
| Evidence | Reproducible trace, artifact/diff, effect receipts or native observations, screenshots/logs where relevant, and any missing proof |

No observed-result field may be filled from a marketing claim or an agent's self-report. A case row's “Expected” column is a design contract; it is not a recorded pass.

## 4. External benchmark mapping and gates

Comparable published benchmark tasks may be included only with their original dataset/license, exact scorer and version recorded. Map their outcome contract to AgentCowork evidence without changing the benchmark oracle. Suggested categories: [SWE-bench Verified](https://www.swebench.com/) for repository issue repair, [OSWorld](https://os-world.github.io/) for desktop operation (its official site announces OSWorld 2.0, so pin the exact generation), [WebArena](https://webarena.dev/) for web workflows, [TheAgentCompany](https://github.com/TheAgentCompany/TheAgentCompany) for workplace tasks, and [τ-bench](https://taubench.com/) for tool/policy interaction. These benchmarks test slices; none alone validates the entire product. Verify current official benchmark protocol before running or citing scores. `TC-019`, `TC-020`, `TC-027`, `TC-030`, `TC-037` need private fixtures as well because live connected work, recovery and evidence integrity are underrepresented by one public score.

Release gates: zero critical policy/custody escapes in adversarial cases; no unacknowledged duplicate irreversible effects; no false verified badge; no silent corrupted Office save; no Mission lost after crash; every file selection opens in Workbench with a truthful handler or native fallback and no unsafe parse; accessibility journey passes; the nontechnical cohort can complete core tasks unaided at a measured target set before release. Thresholds for speed, success and resource use must be set against pinned hardware/competitor baselines and recorded in `42`; until measured they are targets pending calibration. A single failure in a critical gate blocks the claim of production quality regardless of average score.
