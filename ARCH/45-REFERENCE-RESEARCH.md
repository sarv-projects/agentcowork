# 45 — Reference systems and evidence ledger

> Status: architecture review, 2026-09-28. This is evidence, not a dependency mandate. A repository inventory and its execution paths were inspected at the pins below; this is not a claim that every source line in these very large repositories was semantically audited. Recheck upstream before implementation. Product behavior claims require an official source or a reproducible source path.

## Method and confidence

The review enumerated repository structure, then traced launch, agent registration, MCP/skill registration, scheduling, workflow execution, credential use and user-facing control through source. `ARCH/44-ABSORB-REGISTER.md` retains earlier research; this file records new source-grounded findings. Source references are immutable commit links where a pinned checkout was available. An absent source is recorded as a limit, not filled by inference. UI and market claims from vendor documentation are directional; no comparative usability study or benchmark has been run yet.

## Current product evidence and limits

Further focused source anchors: [Hermes `abfa59a` tool search](https://github.com/NousResearch/hermes-agent/blob/abfa59a/website/docs/user-guide/features/tool-search.md) describes deferred tool discovery/schema retrieval rather than a flat prompt dump, and its [subagent lifecycle API](https://github.com/NousResearch/hermes-agent/blob/abfa59a/website/docs/developer-guide/subagent-lifecycle-api.md) separates launches from clients. [UI-TARS Desktop `c2ad42e` browser base](https://github.com/bytedance/UI-TARS-desktop/blob/c2ad42e/packages/agent-infra/browser/src/base-browser.ts) uses a browser abstraction over Puppeteer, while its [desktop operator](https://github.com/bytedance/UI-TARS-desktop/blob/c2ad42e/apps/ui-tars/src/main/agent/operator.ts) uses native input automation; the two surfaces support the structured-to-visual fallback design. [SiYuan `60a4387` index queue](https://github.com/siyuan-note/siyuan/blob/60a4387/kernel/sql/index_queue.go) demonstrates persisted incremental indexing with lock/queue handling, useful for AgentCowork's local knowledge graph without copying a full note application. [Cherry Studio `6337297`](https://github.com/CherryHQ/cherry-studio/tree/6337297) was inventoried for multi-provider desktop and skill surfaces; no source-level quality advantage is inferred from the inventory alone.

[llama.cpp server documentation](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md) and [vLLM serving documentation](https://github.com/vllm-project/vllm/blob/main/docs/serving/online_serving/README.md) establish that open-weight models can be served with structured and tool interfaces. They do not establish that any particular model can independently perform a long-horizon cowork task. Eligibility needs a bound harness, hardware probe and scenario evaluation (`46` §7).

[Claude documents connector/browser/computer-use fallback and human computer takeover](https://support.claude.com/en/articles/14128542-let-claude-use-your-computer-in-cowork). [OpenAI documents Work and automations](https://learn.chatgpt.com/docs/get-started-with-work). These official descriptions establish user-visible directions; they do not establish comparative task success or usability. The architecture therefore defines scenario benchmarks in `38-EXPERIENCE-QUALITY.md` and requires measured results before superiority claims. Local models are a selectable worker class when a real adapter and hardware capability probe meet the task contract; model-agnostic does not mean every model can execute every task.
