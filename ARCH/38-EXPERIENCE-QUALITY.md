# 38 — Experience and quality contract

> Status: accepted target architecture under DEC-054/055/066; implementation and usability evidence pending. `48-EXPERIENCE-SURFACES.md` owns final interaction HLD/LLD; `AGENTCOWORK-UI.md` is the earlier v1 baseline where conflicting.

## Progressive interaction

The default surface is simple chat. A bounded answer stays in chat. A substantial goal creates a Mission with a visible contract that can be corrected. Mission Control progressively exposes goal, requirements, milestone/plan graph, running agents, needs-you inbox, artifacts, evidence and cost. Users may explicitly choose an agent/runtime or let capability evidence select one. The UI never labels a task “verified” when evidence is only a worker report. It shows whether an action used an agent-native tool or a Core-mediated capability.

Every user-facing activity label, quantity, target, verification and worker state is backed by a typed event/result or a Core observation with explicit provenance. A missing fact remains unknown/generic. The Experience layer may humanize and group facts, but it may not invent actions, physical cursor movement, counts, completion or verification. A Live Desk is an optional projection of existing Mission/Work state and does not own execution. Continuous pixels require a separately authorized, exact-surface observation path; opening an ordinary task view is not capture consent (DEC-065).

Evidence-backed does not mean static or technical. Live Desk should feel welcoming, polished and satisfying to everyday users, students and experts. Use a clear visual hierarchy and purposeful, brief motion to explain meaningful transitions in recorded work; prefer approachable workstreams, source/output cards and visible checks over raw agents, tools and DAGs. A generic indeterminate “working” treatment is truthful only while Work is authoritatively running. Do not animate a structured/API action as if it were a physical click, or use motion to imply hidden activity, counts or success. Provide a static equivalent, honor system reduced-motion settings, and let the user pause motion without pausing work. Screen-reader announcements follow semantic state changes, not animation frames. Run moderated usability and appeal studies with nontechnical participants as well as technical users; technical review alone cannot establish that the interface is understandable or enjoyable. See DEC-066, INV-43, `48` §4.2.2 and `49` TC-070.

Controls are immediate, consistent and durable: steer, pause, resume, interrupt, cancel branch/mission, change requirement, change budget, replace worker, take over browser/desktop, inspect child agents, review diff/artifact, retry and revert when a real compensation exists. Questions and approvals share one attention queue. A blocked branch does not hide independent running work. Notifications say completed, waiting or blocked and link to the exact state; they are not completion receipts. The timeline is reconstructed from events at human resolution, with technical traces one level deeper. Keyboard, screen reader, contrast, motion and zoom behavior are acceptance criteria, not decoration.

Artifacts sit beside the conversation with version, source inputs, validation and downstream dependents. A user can open “why is this stale?” and see the changed input. Browser login handoff and takeover show which profile/session the agent controls. Native agent extensions are labeled native; host extensions show installation, activation and permission scopes in one panel. MCP catalog visibility is distinct from active access. Collision/override resolution is inspectable. There is no forced “Code vs Cowork” mode selection for the user; task detail emerges from goal complexity, with override available.

## Performance budgets and reliability measurement

Targets must be measured on representative hardware before publication: cold-start to interactive, discovered-agent inventory time, first token, shared-tool attach time, mission projection rebuild, large artifact preview, browser takeover latency, idle CPU/RAM, and background power use. No arbitrary target is presented as achieved. Discovery is staged/cached so one slow CLI cannot block startup. Lazy MCP startup avoids spawning every configured server. Event projections paginate and virtualize long timelines; context and tool schemas are relevance loaded. Large traces/artifacts are referenced, not shoved into the chat stream.

Quality is measured by scenario completion, intent correctness, side-effect correctness, evidence completeness, recovery after injected crash, permission friction, user corrections, time/cost, and accessibility. A benchmark suite covers at least: connected email/Drive/Sheets task, browser-only YouTube research, desktop-app task, office artifact creation, repo coding task, heterogeneous agent team, multi-day resume, workflow capture/publish, and stale artifact regeneration. Evaluate on the same task inputs and human review rubric against current official competitor products; record dates, versions, device/hardware and limitations. “Near 100%” is an aspiration, not an architecture guarantee. No claim of beating a competitor without measured evidence.

Live Desk quality adds task comprehension, status recall, perceived clarity/appeal, visual comfort, distraction, and preference between motion/static modes. Test whether users correctly understand what is happening, what is finished, and what needs attention; do not substitute “liked the animation” for correctness or accessibility. Calibrate frame-time, memory and CPU/power impact on pinned reference hardware before setting thresholds. W3C pause/reduced-motion requirements and platform guidance inform the implementation, but usability evidence must come from AgentCowork studies.
