# Windows v1 validation runbook

This is the operator procedure for a later Windows validation run. It is a
fail-closed evidence procedure, not a claim that the current tree or a current
binary is qualified.

The fixed locations are intentional:

- **Copy path:** `C:\Users\sonali\Desktop\tests\AgentCowork`
- **Evidence path:** `C:\Users\sonali\Desktop\tests\evidence\<timestamp>`

`<timestamp>` is generated by the runner as `yyyyMMdd-HHmmss-fff` (with a
collision suffix if needed). The evidence bundle contains provenance,
per-command logs, `results.csv`, `summary.json`,
SBOM output when available, and `evidence.sha256`.

## 1. Scope and source snapshot

Run the procedure from the required parent directory:

```powershell
Set-Location 'C:\Users\sonali\Desktop\tests'
$Repo = 'C:\path\to\the\source\working\tree\AgentCowork' # replace; this is the source, not the copy
& (Join-Path $Repo 'scripts\run-windows-v1-validation.ps1') -Repo $Repo
```

`$Repo` is deliberately required. If it is omitted, the runner stops with an
error explaining that it must name the source directory containing
`package.json`, `crates\`, and `src-tauri\`. The runner never guesses a source
path. Do not pass the fixed copy path as `-Repo`; the source and destination
must be different directories.

The runner copies the **current working tree**, not a clean checkout. It copies
tracked and untracked implementation files, including uncommitted changes that
are present when the run starts. It does not claim that the source was clean.
Before copying it records:

- `git rev-parse HEAD`, branch, and `git status --short --branch`;
- `git diff --binary HEAD` as `working-tree.patch` (common secret-shaped
  values are redacted; review the patch before sharing it);
- untracked file names, sizes, and SHA-256 hashes in
  `untracked-files.txt` and `untracked-file-hashes.csv` (not untracked
  contents);
- `provenance.json`, tool-version files, and per-command logs.

Git history itself is not copied. In the copy, the runner initializes a local
Git index only when Git is available so Git-aware inventory gates can enumerate
the copied snapshot. That index is not source history and is not a clean-status
claim.

The copy uses `robocopy /E /XJ` and excludes at least:

- `.git`, `.env*`, `.tauri`, credential/key/PFX/PEM files, signing material,
  `credentials*`, `secrets*`, `service_account.json`, and auth/config secret
  files;
- SQLite/SQLite3, vault, database, and log files;
- `node_modules`, `target`, `dist`, `.cache`, `.turbo`, coverage, code-intelligence
  caches, virtual environments, and generated coordinator/Tauri output.

The post-copy audit fails if an excluded filename or directory is found. Build
outputs generated later by the validation commands are evidence-side outputs of
the copied tree, not files copied from the source.

## 2. Safety, interpretation, and exit status

Standard checks run by default. Live checks are opt-in with `-Live`; they must
run on a disposable Windows host or VM, never on a machine containing valuable
local data. `-AllowUnsignedBuild` is an explicit escape hatch for a disposable
build inspection only; an unsigned artifact is not release evidence.

The runner uses explicit per-command log redirection rather than
`Start-Transcript`, captures `$LASTEXITCODE` immediately after each native
command, and never turns a missing command or a test's `SKIP` marker into a
pass. `FAIL` and `BLOCKED` both make the final process exit nonzero. A
`BLOCKED` row is a truthful statement that the evidence could not be collected;
it is not a softer pass.

Useful switches:

```powershell
& (Join-Path $Repo 'scripts\run-windows-v1-validation.ps1') -Repo $Repo -Live
& (Join-Path $Repo 'scripts\run-windows-v1-validation.ps1') -Repo $Repo -Live -ReuseCopy
& (Join-Path $Repo 'scripts\run-windows-v1-validation.ps1') -Repo $Repo -Live `
    -RunInstallDrill -RunUpgradeDrill -RunRollbackDrill `
    -RunSigningInspection -RunUpdaterInspection
```

`ReuseCopy` permits an in-place refresh of the fixed copy. It does not delete
stale files; use it only after reviewing the destination. The install, upgrade,
and rollback switches make the runner record the requested manual drill but
still do not launch installers automatically. Follow the destructive procedure
in §7 on a disposable VM and attach its transcript.

## 5. Explicit P70.E1–E12 qualification

The runner invokes `node scripts/release-qualify.mjs --execute --json` and
records one row per returned item. It maps `PASS` to `PASS`, `FAIL` to `FAIL`,
and both `RUNNABLE` and `BLOCKED` to `BLOCKED`; a status is never inferred from
a command's zero exit code. The current harness's exact status contract is in
`scripts/release-qualify.mjs:2-26`, and the P70 definitions are in
`TODO.md:2600-2613`.

| ID | Required evidence | Live/default treatment |
|---|---|---|
| `P70.E1` | Kernel gate section clear | Machine check; no live host required. |
| `P70.E2` | Rust, UI, vendored core, and coordinator suites, fmt, and clippy | Standard suite; no result is inferred from a skipped leg. |
| `P70.E3` | Doc sync, cross-document references, and IPC parity | Standard gate; broken IPC counts are failure. |
| `P70.E4` | Security/red-team suite | Standard security gate; missing cargo is `BLOCKED`. |
| `P70.E5` | Real ACP, Chrome/CDP, Office oracle, and vault hydration | `-Live` only; absent tools/services/hosts are `BLOCKED`. |
| `P70.E6` | Live model/edit-ladder/shadow-preflight/agent soak | `-Live` plus credentials/repository; never default PASS. |
| `P70.E7` | Crash/failure-injection L1–L7 | Standard where the real debug core exists; missing binary is `BLOCKED`. |
| `P70.E8` | N-1→N upgrade and rollback evidence | Two sequential Windows builds and a real host; otherwise `BLOCKED`. |
| `P70.E9` | Clean-machine install → first run → provider → task → uninstall | Disposable clean Windows VM; otherwise `BLOCKED`. |
| `P70.E10` | Performance and size/RSS budgets | Standard hermetic benches plus measured artifact/RSS inputs; absent measurements are `BLOCKED`. |
| `P70.E11` | Honest capability audit | Standard static audit; seed/mock-shaped shipping data is `FAIL`. |
| `P70.E12` | Single recorded E1–E11 sign-off | Only a fully passing record can be `PASS`; `--record` is not used to turn blockers into passes. |

After all live evidence is attached, the release qualification command may be
run explicitly:

```powershell
node scripts/release-qualify.mjs --record '<version>'
```

The record command is expected to refuse while any item is `BLOCKED` or
`FAIL`; that refusal is evidence, not a runner defect.

### 6.7 Install, upgrade, rollback, signing, and updater

These are live host procedures, not source-tree tests. Use a disposable Windows
VM and preserve screenshots, process output, installer paths, and data-state
observations in the evidence directory.

**Install → first run → task → uninstall (P70.E9).** For an NSIS artifact:

```powershell
$installer = 'C:\path\to\AgentCowork_<version>_x64-setup.exe'
Start-Process -FilePath $installer -ArgumentList '/S' -Wait
# Launch the installed app, record first-run/setup state, configure a provider
# through the vault, run one real task, and record the result before uninstalling.
```

For an MSI artifact use the corresponding package path and record the result of
`msiexec /x <msi-path> /qn` in the disposable VM. Do not put a provider secret,
vault passphrase, certificate, or token on the command line.

**N-1 → N upgrade (P70.E8/C5).** Install N-1, create durable state, install N
over it, and record vault hydration, Work/events, checkpoints, memory,
calendar, automations, and audit-chain verification. The procedure is the
ordered drill in `docs/updating.md:131-150`.

**Rollback.** Reinstall N-1 over the migrated data and record the expected
newer-schema refusal (or the documented transparent case) before restoring N.
The exact honest failure modes are in `docs/updating.md:127-150`. A failed
rollback is `FAIL`; an unrun drill is `BLOCKED`.

**Authenticode inspection.** Never print certificate values or secret material:

```powershell
$artifact = 'C:\path\to\AgentCowork_<version>_x64-setup.exe'
Get-AuthenticodeSignature -LiteralPath $artifact |
    Select-Object Status, StatusMessage, SignerCertificate, TimeStamperCertificate |
    Format-List
$signtool = (Get-Command signtool.exe -ErrorAction Stop).Source
& $signtool verify /pa /all /v $artifact
```

`Status` must be `Valid` and the countersignature/timestamp must be present for
release evidence. A missing certificate is `BLOCKED`; `UnknownError`,
`NotSigned`, or an untrusted chain is `FAIL`.

**Updater signature inspection.** Extract only the public trust anchor to the
evidence directory and verify the signed manifest with the approved minisign
client:

```powershell
$config = Get-Content '.\src-tauri\tauri.conf.json' -Raw | ConvertFrom-Json
$config.plugins.updater.pubkey | Set-Content '<evidence-path>\updater-public-key.txt' -Encoding ASCII
$manifest = '<bundle-path>\latest.json'
$signature = '<bundle-path>\latest.json.sig'
minisign -Vm $manifest -P '<evidence-path>\updater-public-key.txt' -x $signature
```

The updater trust contract and fallback rules are in
`docs/updating.md:1-34,81-94`. Never substitute a private key, password, or
raw cookie/session file for the public key.

## 7. Artifact, PE, hash, and evidence inspection

After a build, inspect the actual files rather than trusting a task's label.

### Authenticode and updater signatures

```powershell
$bundle = 'C:\Users\sonali\Desktop\tests\AgentCowork\src-tauri\target\x86_64-pc-windows-msvc\release\bundle'
Get-ChildItem -LiteralPath $bundle -Recurse -File -Include *.exe,*.msi |
    ForEach-Object {
        $signature = Get-AuthenticodeSignature -LiteralPath $_.FullName
        [pscustomobject]@{
            Path = $_.FullName
            Status = $signature.Status
            Signer = if ($signature.SignerCertificate) { $signature.SignerCertificate.Subject } else { '' }
            Timestamp = if ($signature.TimeStamperCertificate) { $signature.TimeStamperCertificate.Subject } else { '' }
        }
    } | Format-Table -AutoSize
```

Use `signtool verify /pa /all /v <artifact>` for each executable and installer.
For the updater, use the minisign command in §6.7 with the public key from
`src-tauri/tauri.conf.json`. A signature inspection that cannot locate its
artifact or trust anchor is `BLOCKED`.

### PE architecture

```powershell
$dumpbin = (Get-Command dumpbin.exe -ErrorAction Stop).Source
& $dumpbin /headers '<bundle-path>\AgentCowork.exe' | Select-String -Pattern 'machine|8664|AA64'
& $dumpbin /headers '<bundle-path>\bin\coordinator.exe' | Select-String -Pattern 'machine|8664|AA64'
```

Record the target and observed machine (`x64`/AMD64 or `ARM64`) for the app and
bundled sidecar. A missing `dumpbin`, missing binary, or architecture mismatch
is `BLOCKED`/`FAIL` according to the observed evidence; do not infer it from
the requested Rust target.

### Artifact hashes

```powershell
Get-ChildItem -LiteralPath $bundle -Recurse -File |
    Get-FileHash -Algorithm SHA256 |
    Export-Csv '<evidence-path>\artifact-hashes.csv' -NoTypeInformation -Encoding UTF8
certutil -hashfile '<artifact-path>' SHA256
```

Compare installer/updater hashes with the generated `SHA256SUMS`. Keep the
hash file beside the release surface output in the evidence directory.

### Evidence logs and bundle hash

```powershell
$evidence = '<evidence-path>'
Get-Content (Join-Path $evidence 'results.csv')
Get-Content (Join-Path $evidence 'summary.json')
Get-ChildItem (Join-Path $evidence 'logs') -File | Sort-Object Name
Get-Content (Join-Path $evidence 'evidence.sha256')
Select-String -Path (Join-Path $evidence 'results.csv') -Pattern 'FAIL|BLOCKED|PASS'
```

`summary.json` and `results.csv` must agree on counts. The final process exit
code is nonzero if either file contains `FAIL` or `BLOCKED`. Archive the
complete evidence directory only after checking that no secret values were
captured in command output or the patch snapshot.
